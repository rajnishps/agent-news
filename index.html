The problem

Built for browser tabs, not for agents

The internet's news infrastructure was designed for people reading in a browser — not software that needs to reason over what just happened.

Information overload

One event can spawn hundreds of near-identical articles before an agent finishes reading the first ten.

Duplicate reporting

Agents burn time and tokens re-reading the same facts from five different outlets, one at a time.

No machine-native format

News is built as pages to browse and scroll, not as structured data an agent can query and reason over.

No sense of change

A story at 8am can look nothing like it does by 6pm — there's no simple way to ask "what changed?"

How it works

From raw coverage to a live event graph

Four stages turn a flood of duplicate coverage into one evolving, sourced object per real-world event.

01 — Ingest

Collect

Continuously pull from licensed feeds, publisher APIs, and official releases.

02 — Cluster

Deduplicate

Group coverage of the same event using entities, timing, and semantic similarity.

03 — Extract

Structure

Pull individual claims, entities, sources, and confidence — not just a summary.

04 — Serve

Expose

Publish events via REST API, streaming, webhooks, and MCP tools for agents.

What an agent gets back

One event object, not a page of links

Every response is sourced, scored, and diffable against its previous state.
